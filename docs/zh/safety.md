# 机器人操作安全

使用 EmbodiRun 操作真实机器人前，请完成工作空间风险评估，熟悉厂商安全手册，
并确认硬件急停可用。下文介绍运行时提供的软件防护和操作检查步骤。

## 软件防护措施

EmbodiRun 提供：

- 对每步关节和夹爪运动设置变化量上限（`step_limit_mode: clip` 或 `reject`），
- 按动作块执行，以动作块边界限制单次执行范围，
- 模型动作与手动输入之间的控制仲裁，
- 人工接管与自锁式软件急停，
- 推理失败时不提交动作。

EmbodiRun **不**提供碰撞避免、工作空间监控、
力限制，也不提供经认证的功能安全路径。动作裁剪是一种
速率限制，而不是障碍物规避。

## 软件停止与硬件停止

软件急停在运动队列之外进行自锁，取消活动
工作，并清除待处理的动作。它运行在 Control 进程中。ARX5 或
SO-101 适配器会将停止与当前 SDK 调用串行化，因此被阻塞的 SDK 调用
可能会延迟物理停止。FR3 适配器允许并发停止。

始终将硬件急停保持在触手可及的范围内。软件停止是一层
额外的保护，而不是替代品。

## 控制权与连接管理

- 每个 Control 服务拥有一个机器人以及一个仲裁器。
- 模型动作使用有界 FIFO；手动动作只有一个待处理槽位
  （新输入覆盖尚未执行的旧输入）。
- 获取手动控制会取消模型工作，包括在接管之后
  才到达的推理结果。
- 释放手动控制允许启动新的模型任务；它绝不会恢复
  已取消的任务。
- 任务完成后，适配器执行保持/停止操作，机器人连接继续保留，
  不会自动返回原点。
- 服务关闭会释放硬件。

## 操作员检查清单

运行任务之前：

1. 阅读本文档以及 [`control.md`](control.md)。
2. 确认硬件急停可用，并保持其触手可及。
3. 确认工作空间无障碍，且运动范围内没有任何人。
4. 在 YAML 中核实标定、相机角色以及 `step_limit_mode`。
5. 确认检查点的状态/动作维度与绑定一致。
6. 在操作员在场的情况下，依次运行 `validate`、`probe`、`init`、`up`。
7. 从 `--max-steps 1` 和较小的 `--chunk-steps` 开始。

任务执行期间：

- 关注机器人本身，而不仅仅是终端。
- 准备好随时使用人工接管或软件停止。
- 将已接受的请求视为“进行中”，绝不要视为任务成功。

## 发生故障时如何处理

- 推理失败 → 不提交任何动作。
- 未知的执行结果 → 请求会被报告为未知，并且不会
  自动重新发送。
- 未经确认的停止 → 绝不会被报告为成功。
- 取消 → 迟到的推理结果会被丢弃，而不会被执行。
- 急停 → 待处理的模型动作与手动动作都会被清除。

## 报告安全问题

提交 issue 时请附上配置概要（隐去地址与密钥）、
运行命令、实际现象，以及是否触发了硬件停止。请勿
包含检查点路径、令牌或个人数据。
