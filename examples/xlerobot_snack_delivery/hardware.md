# Hardware and software bill of materials

This page separates the minimum platform from the optional acceleration and
operator equipment. Prices are planning estimates in USD, before shipping,
tax, import fees, 3D printing, and tools. They are not quotations.

| Item | Minimum specification for this recipe | Required | Planning price | Notes and source |
|---|---|---:|---:|---|
| XLeRobot mobile base + dual SO-101 arms | Dual-wheel XLeRobot 0.4-style build, two arm buses, battery, cart, motor wiring | Yes | About **$660** for the community basic build; the developer assembly kit was listed at **$579** excluding battery and IKEA cart | The upstream project gives the cost breakdown and exclusions in its [README](https://github.com/Vector-Wangel/XLeRobot); the dual-wheel assembly notes are in the [XLeRobot hardware docs](https://xlerobot.readthedocs.io/en/latest/hardware/getting_started/assemble_2wheel.html). |
| SO-101 servo and bus parts | Each follower arm has six STS3215 motors, one bus adapter, cables, brackets, horns, gripper, and calibrated limits | Included in the platform above | Included above, or roughly $150–300 per arm when sourced separately | Use the [LeRobot SO-101 assembly and calibration guide](https://huggingface.co/docs/lerobot/main/assemble_so101). It describes motor IDs, wiring, assembly, and follower/leader calibration. |
| Computing device | AGX Orin 64 GB class device, or an equivalent Linux host with enough USB/GPU capacity for the owner and configured VLA service | Yes | NVIDIA lists the AGX Orin 64 GB Developer Kit at **$3,499**; an Orin Nano Super is listed at **$399** but is not a validated replacement for this VLA deployment | NVIDIA's [Jetson FAQ](https://developer.nvidia.com/embedded/faq) is the price and platform reference. Developer kits are for development, not production deployment. |
| Cameras | One front camera and left/right wrist cameras with stable owner-defined roles and timestamps | Yes | $30–220 per camera as a planning range | The XLeRobot project lists about **+$30** for stereo RGB and **+$220** for a RealSense RGB-D head camera. This recipe requires owner-published frame roles; it does not require a particular camera brand. See the [LeRobot camera/robot docs](https://huggingface.co/docs/lerobot/index). |
| Battery, charger, wiring, mounting, and emergency stop | Rated for the base and two arms, with a physical stop accessible during testing | Yes | $150–500 allowance | The XLeRobot basic price excludes some of these items. Choose electrical ratings locally; do not infer safe current from the recipe. |
| Operator input | DualSense, keyboard, or another owner-supported teleop input for recording a route | Only for recorded-route mode | $0–80 | The input belongs to the owner/recording workflow, not the recipe process. |
| Development workstation | Linux/macOS machine for this repository, configuration, logs, and SSH access | Yes | Not separately estimated | It does not need to own the robot serial ports. |
| Storage and network | 100 GB free working space, reliable local network or SSH path between workstation, owner, and Control | Yes | Not separately estimated | Keep raw recordings and private deployment files outside the public repository. |

The basic XLeRobot estimate is therefore not the complete recipe budget. A
realistic planning range is roughly **$1,000–$2,000 without an AGX**, or
**$4,000–$6,000 with a new AGX Orin Developer Kit**, depending on how much of
the platform, battery, camera, and compute hardware is already available.

## Software bill of materials

| Layer | Required setup | Owned by |
|---|---|---|
| Recipe host | Python 3.10+, this repository, and the public Deploy client | Recipe user |
| XLeRobot owner | `integrations/xlerobot_owner` with the hardware/camera/recording extras, one serial owner, stable device identities, and read-only startup checks | Deployment operator |
| Deploy Control | A configured local/SSH Control service exposing `/v1/observe`, `/v1/propose`, and `/v1/execute` | Deployment operator |
| VLA | A configured Pi0.5/VLA runtime selected by the manipulation runtime ID | Inference/deployment operator |
| Route source | Either recorded outbound/return action chunks or route artifacts generated by RPent from a diagram | Recording tool or RPent |
| Evidence mapping | Owner observations exposing freshness, base readiness, stop confirmation, and grasp evidence | Owner integration |

The recipe does not carry credentials, model checkpoints, or private device
paths. Those remain deployment configuration. The recipe process can run in a
trusted loopback/SSH setup or behind a deployment-owned authenticated gateway.

## Physical bring-up order

1. Assemble the base and arms using the XLeRobot and SO-101 guides. Label the
   two arm buses and every motor before applying power.
2. Configure motor IDs and calibrate both arms while the base is mechanically
   secured. Read back joint limits and units; do not copy a calibration file
   from another robot.
3. Mount the front and wrist cameras. Bind them by stable device identity,
   then verify that the owner reports fresh state and camera timestamps.
4. Install the owner and Control software with the setup script. Start in
   read-only mode, check feedback, camera roles, stop state, and serial locks,
   then enable motion only after the protected test area and emergency stop are
   ready.
5. Select a route source. Record one demonstration or ask RPent to turn a
   route sketch into the two public route artifacts. Validate the artifacts in
   `--mode plan`.
6. Calibrate the right-arm handover pose and gripper opening on the target
   robot. The example values are starting data from the earlier experiment,
   not a substitute for live-limit and clearance checks.
7. Run `dry-run`, then a slow supervised hardware run. A completed HTTP job is
   not physical success; retain the owner recording and final human receipt
   confirmation.
